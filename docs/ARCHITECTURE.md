# 工程与剧情制作

入口只加载剧情、美术清单并装配游戏。游戏控制器是运行状态的写入入口；阅读控制器负责打字、自动／快进和救援计时；输入绑定可通过AbortController整体释放；场景展示只处理背景、立绘和CG。面板通过只读快照及明确动作访问控制器，剧情图接收单独的上下文和回溯动作。

纯引擎处理条件与因果变化。共用存档校验同时服务浏览器读取、导入和节点快照；导入完成校验并写入持久化后才切换当前数据。无法读取的本地原文不被内存模式覆盖，可单独导出。自动进度、六手动槽、全局收集和每节点最多三份路线记录维持原协议。

## 修改剧情

1. 编辑`story/chapters/`中对应章节的JSON。每份包含章节信息及该章场景；证据、回响、结局定义与稳定顺序在`story/metadata.json`。
2. 在原段落上修改`text`。依赖前置选择时，增加`variants: [{when, text}]`，首个匹配项生效，无匹配则使用原文。对白的`when`会影响可见索引，不能把文字变化误写成段落过滤。
3. 运行`npm run story`，随后`npm run check`与`npm test`。输出为确定性的UTF-8，校验成功才原子替换运行数据。

本轮兼容保证要求场景与选项ID、段落顺序、可见条件和因果规则不变。若未来需要改变这些字段，先设计显式存档迁移，再更新兼容测试；不能通过重录基线消除失败断言。

## 修改界面

组件样式分为基础、首页、场景、面板、剧情图和演出效果，由现有样式入口按固定顺序加载。优先修改对应组件的规则；响应式差异保留在该组件内。带`display`的dialog规则必须限制在`[open]`状态，避免关闭后残留。

资源替换需独立更新美术清单和视觉验收；本轮43个生产资源的基线哈希固定。历史原图保留，普通工程重构不重新编码或改写素材。

## 检查与开发工具

Node.js 24+运行`npm run check`与`npm test`。Python用于生成剧情；游戏本身通过任意静态HTTP服务运行，无安装步骤。浏览器脚本需要Python Playwright；美术脚本另外需要Pillow和NumPy。通过`CANXIANG_BROWSER`指定浏览器可执行文件，Windows未指定时检测Edge，其余环境使用Playwright安装的Chromium。通过`CANXIANG_BASE_URL`复用已有服务，否则公共启动器使用本地随机端口。

`?debug=1`仍提供测试诊断对象；普通游玩不暴露该对象。旧浏览器脚本保留兼容调用，但产品面板和剧情图不依赖诊断接口。
